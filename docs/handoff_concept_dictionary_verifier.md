## 3. 概念字典：一份定义、确定规则推送

### 3.1 不判断模型是否“需要”概念

不要新增 LLM 路由器判断模型懂不懂。按工具名、指标名、返回字段和实际参数查确定映射；相关概念自动随工具结果返回。模型不用先调用字典工具。

字典建议保存在版本控制下的 YAML/JSON，配一个加载模块。唯一来源供系统提示、工具说明、结果渲染使用，避免多处独立维护定义。

每条概念至少含：`id`、名称/别名、定义、公式（适用时）、输入要求、单位/期间约束、常见误用、解释边界、版本。概念字典是通用业务元数据，不包含案例答案、管理层解释或本题解题路线。

### 3.2 基础定义默认提供

每次运行自动提供精简基础块：同比/环比、百分比/百分点、余额/期间发生额、单位、公司财年映射、真实/合成数据边界。预算建议不超过约 1000 中文字符，不注入整个字典。

财年映射必须由现有公司配置生成，不能把联想 3 月末财年规则套给 Dell/HP。例如联想 FY2027Q1 对应 2026-04-01 至 2026-06-30。

### 3.3 首批概念与工具映射

| 概念 | 必须明确的内容 | 自动触发 |
|---|---|---|
| YoY 同比 | 本期对上年同一期间；(本期−比较期)/比较期，遵守现有负数/零分母规则 | variance 的同比行 |
| QoQ 环比 | 本期对上一季度，不能称同比 | variance 环比行、peer_compare、seasonal_check |
| 平均余额 | (期初＋期末)/2，与发生额期间对应 | working_capital |
| DIO | 平均存货/单季 COGS×实际天数；平均存货为分子 | working_capital 返回 dio |
| DSO | 平均应收/单季收入×实际天数 | working_capital 返回 dso |
| DPO | 平均应付/单季 COGS×实际天数；是近似口径，非合同付款期限 | working_capital 返回 dpo |
| CCC | DIO＋DSO−DPO；不能单独证明现金流或资金来源 | working_capital 返回 ccc |
| 毛利率/经营利润率 | 相应利润/同期间收入；比率与金额不能替换 | query_metric 返回相应指标 |
| 百分比/百分点 | 相对变化与比率差不同：15%→16% 是 +1pp，相对 +6.67% | 返回比率或变化率 |
| 季度/累计 | Q2 与 H1、Q3 与 9M 不同；利润表发生额与余额不同 | 查询有关期间型指标 |
| z/历史分位 | 当前环比与历史同财季环比比较；标明历史 n，异常不等于经营根因 | seasonal_check |
| 同行比较 | 当前工具是同自然季度的环比；截止日可能不同，同向不证明同一因果 | peer_compare |

定义必须核对实际算法。遇到指标符号、零分母、季度/累计数据语义不明确，先记录，不得靠字典文字掩盖实现差异。本轮不擅改算法。

### 3.4 结果绑定本次口径

概念说明和具体数据要同时返回。不能只多写一段“同比是什么意思”，却仍让 `change_pct` 不带比较口径。

工具结果增加可追踪的 metadata，至少涵盖适用字段：

- 概念 ID 与字典版本；
- 指标、字段、单位及数值缩放（0.3431 是 ratio，34.31 是 percent）；
- 比较类型、本期与比较期；
- 平均/期末余额、发生额时间段与天数（适用时）；
- 数据性质：真实、合成、未知，按实际来源确定，不编造。

示例语义（结构可按项目调整，兼容现有数值字段）：

```json
{
  "metric": "inventory",
  "comparison": "qoq",
  "current_period": "FY2027Q1",
  "reference_period": "FY2026Q4",
  "change_pct": 0.3430681216,
  "value_unit": "ratio",
  "display_value": "34.31%",
  "definition_ids": ["qoq", "stock_balance"],
  "dictionary_version": "v1"
}
```

多公司、多期间、多指标的口径要绑定对应行或字段，不能只在整张表顶部写一个笼统单位。variance 的同比、环比、贡献度行要区分；贡献度不能自动称为同比。

### 3.5 渲染、召回与导出

- 元数据存入 Result Store，并进入 `results.json`；模型实际可见的工具消息显示精简相关定义与口径。
- 定义/关键口径块不能被普通数据行截断吞掉。预算内优先保留；无法完整显示时明确提示。
- recall 应还原相关定义与口径；压缩存根保留概念 ID、版本、比较类型和必要期间，复用现有压缩机制，不另建系统。
- trace/run_meta 记录字典版本及哪些工具结果注入了哪些概念，不能只记录“字典已启用”。
- 初始数据包走同一套规则，避免只覆盖模型主动调用。
- 第一版无需新增概念查询工具；以后可补充，它不是本轮验收前提。

注意：S01 当前明细 SQL 未返回 synthetic 标记。若本轮只补元数据，确实来自 facts_detail 的结果应从实际来源保留性质；无法确认必须标 unknown，不能默认真实。无需补真实业务明细或改 ETL。不声称一个警告就能消除模型使用合成证据的问题。

## 4. 核验器：修冲突，保留财务数字要求

### 4.1 置信度使用结构化元信息

优先采用明确可验证的协议，而非全局忽略 0–1 小数或“置信度”附近的数字。

- final_answer 增加可选的结构化主观置信度字段（建议 `assessment_metadata`，含假设 ID、说明、confidence、kind=model_subjective）。
- confidence 仅接受有限的 0–1 数值，明确不是财报事实、不是已校准概率，不要求 rid。
- 模型提交的 answer_md 不重复写置信度数字；展示层在核验后渲染结构化元信息，并显式标注“模型主观评估”。不把该展示文本再次当成财务数字扫描输入。
- 同步 system/tool description/attribution skill，移除会让模型在正文嵌入 confidence JSON 的旧要求，保留旧运行包可读性。旧协议仍可使用，只是正文元数字不自动豁免。
- 所有财务数字继续走 claims；如果正文写“毛利率 0.6%”却无引用，必须拒绝。不得通过把财务数字塞进 metadata 使它自动获准为业务事实。

本轮不实施全面的语义 claim 匹配。明确记录：数字存在于 rid 中，并不证明模型正确解释了该数字；口径元数据是以后完善这项检查的基础。

### 4.2 数字扫描与显示舍入

- 正确排除 Markdown 行首列表序号，如 `1. `、`2) `；仅排除序号本身，不排除其后财务数字。
- 公式常量不全局豁免：由工具口径元数据提供可追踪的天数/定义，不能因其是 91 或 365 就放行。
- 保留已有引用存在性、单位核对、勾稽和最终状态检查。
- 在单位归一后，合理显示舍入不得仅因固定相对容差被拒：0.2418 天→0.24 天应接受，47.2317→47.23 天应接受。
- 舍入判断从原始显示文本/明确显示精度获取精度；若 claim schema 丢失尾零，需保留显示字符串或等价精度字段。不要从 float 猜显示位数，不允许模型随意扩大 tolerance。
- 不扩大所有数字的全局容差。量级错误、错误单位、方向错误仍应拦截；复杂语义尚未实现的检查要诚实列为限制。
- 本轮无需重做整个评分器；运行时 verifier 与 selected_v1 的答案显示精度政策保持一致，内部 gold 自查容差不用于拒绝合理回答。

## 5. 离线验收：先验证规则，再用 API

增加必要的、有区分力的回归检查，复用现有测试框架：

1. working_capital 结果自动出现 DIO/平均余额/天数定义；初始数据包与 recall 元数据不丢失。
2. peer_compare 与 seasonal_check 清楚标注 QoQ；variance 同时输出同比环比时两种口径不混。
3. 一个多指标结果的单位/字段定义正确，非联想公司财年映射不误用。
4. 合成明细结果不能被标记为真实；未知来源不伪装成真实。
5. 合法结构化主观置信度无 rid 可接受；越界/非有限 confidence 拒绝；无引用财务数字依旧拒绝。
6. `2. 收入为 123.45` 只排除序号 2，仍检查 123.45。
7. 正确舍入通过，错误金额/单位不通过；不误用内部自查容差。
8. 注入内容只有通用概念与来源元数据，无 selected_v1 gold、required_inputs、评分断言、管理层原文。

先跑上述回归及受影响的既有检查。通过后再进入 live，不为通过测试重写业务题。
