# 联想归因分析候选集：抽取规范、Few-shot 与人工审核

日期：2026-10-05。接收者：用户选择的 Flash 或其他开发模型。

当前授权：从联想公开财报中，由新到旧抽取约 50 条候选，交给用户与审核模型筛选。只建设归因分析候选集；不构造预测回测集，不自动修改 Agent，不自动启动批量评测。本文推进《prd_eval_optimization.md》的第二阶段候选抽取部分。

## 1. 我们要抽什么

抽取“值得管理层解释的财务变化，以及有证据的解释”，不是只抄一句业绩摘要。优先选择多个指标有冲突、需要分解贡献、区分口径或排除错误解释的问题。

公告通常是管理层讨论，而非真实的问答记录。必须区分：

- `explicit_qa`：原材料确实有提问与回答；记录发言者及定位，否则不能使用此标签。
- `derived_from_management_discussion`：依据管理层讨论改写的分析问题；不得伪称高管原话。
- `analyst_constructed`：依据财报数字构造的验证问题，如“存货下降是否意味着周转改善？”；标明由我们构造。

每个案例有两层答案：

1. **披露参考**：管理层如何解释变化，原文在哪里。它是来源明确的管理层判断，不自动等于已证明的经济因果。
2. **可评分答案**：只看被测 Agent 可获得的真实结构化数字，能够算出、支持或排除什么；不能辨识的原因应该怎样保留为假设。

财务恒等式分解能够解释指标或金额变化的组成；单凭这些分解，不能证明外部需求、价格、汇率或管理行动造成了变化。因此本集是“归因与证据边界分析”，不宣称完成严格的因果识别。

归因 harness 可能帮助预测所需的变量选择与假设检验，但是否提升预测能力仍待后续独立验证。本轮不要求预测题，也不把归因得分当作预测得分。

## 2. 材料与抽取顺序

先读 `data/manual/lenovo_manifest.json`，匹配 `data/raw/lenovo/` 原始 PDF。按真实披露日期倒序，不按文件名字典序。

截至本次检查，本地清单最新一份为 `FY27Q1_130820261201.pdf`，披露日 2026-08-13，报告期末 2026-06-30，即 FY2027Q1。这里的“最新”指本地清单；不声称已经联网核实覆盖全部最新公告。发现缺失或元数据冲突时记录缺口，不捏造财报。

公告原始 URL 在 manifest 中。为每份已用文件计算完整 SHA256；现有 manifest 的 sha256 是截断值，不冒充完整哈希。PDF 从 1 开始的物理页码与印刷页码分开记录。

执行过程：

1. 建立按披露日期倒序的文件清单，记录报告期间、财年映射、是否可正常抽取。
2. 一次处理一份公告，先看财务摘要与业务回顾，再核对财务表、分部附注、调整项目、营运资金相关附注。上下文不足时按章节处理，不把全部财报塞进一次请求。
3. 每份先尝试抽取 3–6 条有价值候选，不以数量为硬指标。每完成一份立即落盘，累计接近 50 条后停止；本轮建议 45–55 条。
4. 发现相同事件在不同公告重复披露，使用同一 `event_family_id`，保留代表性问题，避免靠改写同一道题凑数。
5. 写出当前 DB 支持情况。需要真实分部或附注数字的题保留为补数候选，不用合成数字替代，不擅自实施 ETL 扩展。
6. 自查字段、页码、数值、公式与勾稽，交付候选及缺口清单，然后停止，等待审核。

不要按财报中的经营解释来给 Agent 挑选一组暗示答案的数据。初始数据包沿用系统统一规则；Agent 可补取真实结构化数据。确需扩展数据源时，先整理完整的真实表和来源，待用户裁定后统一纳入数据层。

## 3. 每条候选必须包含的字段

建议每行一个 JSON 对象，以下结构用于抽取交付，评测加载器不应把整行传给 Agent。

```json
{
  "case_id": "LV-FY2023Q3-INV-001",
  "event_family_id": "LV-FY2023Q3-working-capital",
  "question_origin": "analyst_constructed",
  "company": "Lenovo",
  "fiscal_year": 2023,
  "fiscal_quarter": 3,
  "period_end": "2022-12-31",
  "publication_date": "2023-02-17",
  "query": "联想 FY2023Q3 存货下降是否意味着周转改善？请比较上年同期，并说明依据。",
  "sources": [
    {"pdf": "FY23Q3_170220231201.pdf", "url": "从 manifest 填入真实 URL", "sha256": "计算完整哈希", "pdf_pages": [2], "printed_pages": [2], "section": "业务回顾及展望"}
  ],
  "management_reference": {"paraphrase": "管理层披露期末存货同比、环比下降，同时讨论需求疲弱与去库存。", "evidence_spans": []},
  "required_inputs": [],
  "calculations": [],
  "scorable_answer": {"must_include": [], "acceptable_variants": [], "must_not_claim": [], "unknowns": []},
  "db_support": {"status": "ready", "checked_at": "2026-10-05", "missing_fields": []},
  "tags": ["denominator_effect", "inventory_vs_turnover"],
  "difficulty_rationale": "库存余额下降可能误导模型直接判定周转改善。",
  "review_status": "unreviewed"
}
```

填写要求：

- `sources` 定位管理层解释、数字和附注；引用短片段并保留页码，不复制整篇公告。每个关键断言要能对应具体来源。
- `required_inputs` 每个输入写指标、实体/分部、期间、原始金额、原始单位、统一单位、来源页码、单季/累计/时点、原始/重述版本，以及 DB 对应字段或缺口。
- `calculations` 写公式、输入引用、算出的结果和数值容差，不要求模型生成长篇思维链。金额建议按来源精度确定容差；百分比与天数分别说明绝对容差，不能统一随意设 5%。
- `scorable_answer.must_include` 使用可独立判定的原子结论，不是一段要求逐字模仿的参考作文。给出等价表达与合理替代算法。
- `must_not_claim` 列出明确错误及无法证实却被说成事实的原因。没有披露原文可见时，不得强制 Agent 复述管理层原因。
- `db_support.status` 为 `ready / needs_numeric_data / boundary_only / reject`。`boundary_only` 表示适合评测“证据不足但仍完成能完成的分析”，不能把单纯拒答设为优秀答案。
- 模板中的示意字符串必须替换为真实值；找不到的字段填写 null 并解释，不让占位内容混进正式候选。

## 4. Few-shot：五种抽法

以下示例依据已检查的本地原始 PDF 与既有数值材料。它们示范抽取标准，不是新增已验收的数据集。执行者仍需补齐逐个输入的来源与完整 JSON 字段。

### 示例 A：存货下降，周转却变差——当前可测

来源：`FY23Q3_170220231201.pdf` p2 的存货与经营讨论；数字来源还包括本期及上年同期的资产负债表、损益表，以及两期各自前一季度的存货余额。已有核对记录见 `docs/attribution_case_lenovo.md`。

问题（自行构造）：联想 FY2023Q3 存货下降是否意味着周转改善？请与上年同期比较，解释两个指标可能不同向的原因。

输入，单位百万美元：

| 项目 | 上年同期 | 本期 |
|---|---:|---:|
| 季初存货 | 8727.816 | 8417.891 |
| 季末存货 | 8441.581 | 7502.055 |
| 平均存货 | 8584.6985 | 7959.973 |
| 单季营业成本 | 16771.318 | 12654.361 |
| 季度天数 | 92 | 92 |

计算：`DIO = (季初存货 + 季末存货) / 2 / 单季营业成本 × 天数`。上年同期 47.0918 天，本期 57.8708 天，增加约 10.7789 天；季末存货同比约下降 11.1297%。

可评分答案：库存余额下降，但在同一平均余额与季度天数口径下，周转天数上升。平均存货下降幅度小于成本下降幅度，是 DIO 上升的数学解释。对需求疲弱、去库存可提出待验证假设，不能仅凭上述数字把它们宣布为已证实经营原因。

易错点：余额下降直接等于效率提升；把渠道库存当公司账面库存；用收入替代成本算 DIO；用 365 天配单季成本。题面固定这里的计算口径，以便评分公平。

### 示例 B：两个分部增长，为何集团收入仍下降——待补真实分部数字

来源：同一公告 p2 的管理层讨论和 p11 的三个月分部表。问题依据讨论改写，非高管原话。

问题：联想 FY2023Q3 ISG 与 SSG 收入增长，为什么集团收入仍然下降？请拆解各分部与抵销项的贡献。

输入，统一为百万美元：

| 项目 | 上年同期 | 本期 | 变化 |
|---|---:|---:|---:|
| IDG | 17609.684 | 11585.682 | -6024.002 |
| ISG | 1928.783 | 2855.147 | +926.364 |
| SSG | 1497.621 | 1836.435 | +338.814 |
| 抵销 | -909.556 | -1010.658 | -101.102 |
| 集团 | 20126.532 | 15266.606 | -4859.926 |

可评分答案：IDG 下降是金额变化的主要来源，ISG、SSG 增长部分抵消；计入抵销后，四项变化加总等于集团下降额。负贡献/正贡献应说明分母与符号，不强制采用一种百分比表达。

披露参考：管理层讨论需求疲弱与货币逆风；数字本身不能定量区分销量、价格、汇率。

易错点：只比较增长率忽视规模；分部收入直接相加遗漏抵销；把分部贡献说成终极经济原因。当前 `facts_detail` 是合成明细，不可用于本题真实归因；真实表已保存在 `docs/evidence/attribution_case/lenovo_real_segments.csv`，正式评测前需确认它进入统一可查询的数据层。

### 示例 C：调整后利润大增，报表却亏损——待补调整明细

来源：`FY27Q1_130820261201.pdf` p1 财务摘要、p2 经营讨论；正式候选还需核对 p7–9 的非香港财务报告准则定义与调节表。

问题：联想 FY2027Q1 的调整后经营利润增长，但报表经营利润大幅下降，二者是否矛盾？请用调节项说明，区分经营与会计影响。

输入，单位百万美元：本期调整后经营利润 1523；认股权证公允值变动 -1690；其他非现金项目 +186；报表经营利润 19。上年同期分别为 631、+152、+2、785。

计算：`1523 - 1690 + 186 = 19`；`631 + 152 + 2 = 785`。同比变化分解：调整后经营利润 +892，认股权证项目 -1842，其他非现金项目 +184，加总 -766，等于 `19 - 785`。

可评分答案：两个口径不同，不矛盾；报表经营利润下降的调节构成主要是认股权证项目由收益转为大额损失。该项被公告定义为非现金调整；不能从亏损数字推断相同金额的现金流出，也不能据此说公司“没有经营风险”。

披露参考：p2 将认股权证重估主要联系到股价变动。这一原因不应成为仅能看调节数字的 Agent 必答事实。

易错点：调整后经营利润与调整后归母利润混用；经营利润调节桥与归母利润调节桥混用；忽略税及其他非经营项目。不得用这里的三项直接解释归母亏损 -609。当前统一科目表没有这些调整明细，不能先标为 `ready`。

### 示例 D：毛利率改善不代表毛利金额增长——当前可测

来源：`FY23Q3_170220231201.pdf` p2 的毛利率讨论，p17 三个月损益表。

问题：联想 FY2023Q3 毛利率同比改善，是否说明毛利金额也改善？请拆分收入规模与毛利率变化的影响。

输入，单位百万美元：收入 20126.532 → 15266.606；毛利 3355.214 → 2612.245。毛利率约 16.6706% → 17.1108%，提升约 0.4402 个百分点；毛利金额下降 742.969。

一种可接受的确定性分解：令 `G = R × m`，使用 `ΔG = (R1-R0)×m0 + R1×(m1-m0)`，两个部分分别代表该分解口径下的收入规模影响与毛利率影响。其他精确分解也可接受，要求说明交互项分配口径并勾稽到 -742.969。

可评分答案：毛利率改善，但收入下降抵消并超过了利润率提升带来的正向影响，所以毛利金额仍下降。毛利率变化可能与结构、价格、成本有关；没有相关细项时不能断言某个经营原因。

易错点：百分比与百分点混用；拿九个月累计数与三个月单季比；把正向贡献误说成总金额增长。

### 示例 E：财报有经营解释，数字不能唯一识别——边界题

来源：`FY23Q3_170220231201.pdf` p2，管理层提及收入下降、货币兑换负面影响、需求与渠道库存。

不合格问题：请只用收入和资产负债表精确计算销量下降、降价和汇率分别贡献多少，并复述高管的真实原因。

合格改写：联想 FY2023Q3 收入下降，能否仅凭当前美元财务汇总数据确定销量、价格和汇率各自的贡献？先量化可计算的收入变化，再说明还需要哪些数据。

可评分答案：先完成收入同比分析，说明仅凭汇总金额无法唯一拆分；需要销量/出货、可比产品价格、产品结构、各币种收入与汇率或统一口径的恒定汇率调节资料。管理层关于汇率影响的披露留在 evaluator 侧，不能要求 Agent 凭空算出同一结论。

易错点：将公告的“6% 负面影响”未经定义就按 6 个百分点做精确美元分解；猜测销售量或平均售价；把所有未知问题都简单拒答而不做能完成的分析。

## 5. 候选审核、代表性和留出

50 条是候选规模，不是必须全部上线。不要只保留最难题：保留少量基础题检验取数、口径与公式，再以多因素分析和误导性表象题为主，同时保留适量证据边界题。

审核逐条检查：来源真实与定位 → 数字及单位 → 计算和勾稽 → 当前输入可辨识性 → 问题中是否泄漏答案 → 与其他案例是否重复 → 评分是否允许合理等价答案。

复杂度来自至少两种操作的组合，如同比比较 + 分母效应、分部金额贡献 + 抵销、利润调节 + 现金/非现金区分。误导性来自真实的指标冲突和口径陷阱，不用含混题面、错误数字或缺数据的强制猜测来制造难度。

建议审核后先选约 15–20 条当前可测案例作为调优集；若有效且可测的候选不足，缩小集合并报告缺口，不凑数。另留约 8–10 条未用于改方法的案例作版本验收，其余作为后备/补数清单。

划分必须按事件簇，必要时连同相邻期间和同一比较窗口整体分组；同一公告的同一变化换个问法不能跨组。审核可以检查留出题的质量，但其答案、运行结果和错误分析不能用于调优；一旦用过就降为开发集，另留新的验收案例。初期采用私有固定的开发/留出集合，不把留出 gold 写进 prompt、skill 或 harness。

我们不会把 50 条候选提炼为 50 个 skill。人工分析 bad case 后，选择少量通用改动，例如期间与单位核对、金额与比率并看、分母分解、贡献勾稽、口径调节、证据不足时提出待验证假设。每次选一种改动，每题每版本运行一次，对比旧版与新版；确认没有伤害基础能力后再保留。

## 6. 文件交付与停止条件

建议新建 `data/eval/lenovo_attribution_candidates/`，这是 evaluator 侧目录，不是 Agent 工具数据源：

- `source_inventory.csv`：按日期倒序的源文件清单、哈希、是否已读、候选数与跳过原因。
- `candidates.jsonl`：约 50 条、完整字段、原始证据与评分要点，全部初始 `unreviewed`。
- `candidate_index.csv`：case_id、query、期间、event_family_id、类型、难度、DB 支持状态、来源页码，便于人工筛选。
- `extraction_notes.md`：处理到哪份、去重原则、数字缺口、解析问题、实际抽取模型和设置（若已知）。

完成抽取与自查后交付并停止；不要自行打业务 PASS、运行全部 query、做预测、扩功能或调整 prompt。审核通过后再导出两个物理隔离的文件：Agent 侧只有 case_id/query/明确范围；evaluator 侧保留 gold/披露原文/评分规则。既有分析工具只能读取业务数字，不能访问候选目录。

## 7. 可直接发给执行模型的指令

> 请阅读本文件。从本地 manifest 中的联想公开业绩公告按披露日期由新到旧处理，依据管理层讨论与财务表抽取约 50 条归因分析候选。先做 5 条跨类型候选并完成来源、数字、可评分边界与 DB 支持情况自查，再继续累计到约 50 条；这是抽取质量检查，不调用被测 Agent。真实问答与依据讨论改写的问题必须区分。逐条按本文字段交付，参考五个 few-shot 的质量标准，不只复述管理层文字，不强迫 Agent 猜测数据中不可辨识的原因，不使用合成业务明细。每份财报完成后落盘并更新进度，避免中断丢失。发现缺少结构化数字则标为 needs_numeric_data 并列缺口，不自行改 ETL。最终交付 source_inventory.csv、candidates.jsonl、candidate_index.csv、extraction_notes.md，等待用户与审核模型选择正式题。此次不构造回测集、不启动批量 Agent 评测、不修改 harness 或 skill。
