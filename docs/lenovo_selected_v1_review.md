## 3. 最后必须修的五项

### 3.1 运行侧不能提供本题完整解题路线

S05 的 `run_side_visible.metric_definitions` 直接给出 `ΔM=Σ[w0×(m1−m0)]+Σ[(w1−w0)×m1]` 及评分接受条件。该式是本题贡献分析路线，应移到 evaluator 的可接受算法说明，不能作为开放业务题的输入。

运行侧可保留：9M 的期间定义、收入/毛利单位、毛利率=毛利÷收入，以及统一业务指标定义。不要保留“其他完整分解同样接受”“交互项分配并勾稽”等评分指令。

S02/S07 的增量桥、R02 的贡献加总路线、R03 的 Q1 差分步骤也应按同一规则检查：科目和期间定义可见，针对本题的求解步骤移出。若要明确提供公式，则作为另一个“有方法提示的诊断条件”，不把该结果当自主归因基线。不能仅检查有没有出现答案数字就声称无提示泄漏。

### 3.2 内部数值自查精度与答案显示容差分开

当前 S01 DIO 47.2317 天的 tolerance_abs=0.001，会拒绝合理答案 47.23 天（差 0.0017）。金额 1711.812 百万美元若正确表达为 1711.8，也可能被当前 0.001 容差误判。业务答案没有义务输出所有四位小数。

保留精确 gold 与内部算术自查阈值；新增或明确单独的答案核验规则。示例：DIO 显示两位时按相应舍入区间接受，百分比按输出单位和显示精度换算，金额先统一百万/亿等单位再比较。如使用固定业务容差，需覆盖明确允许的舍入精度；勾稽依据未舍入输入验证。

不要为了回答简洁而误判数值错误，也不要因此接受实质性的金额或方向错误。

### 3.3 计算库不是必须逐项复述的清单

当前 numeric_assertions 把平均余额、所有增速、零残差及每个中间步骤都设为目标；S05 虽允许其他精确分解，却仍列出指定算法的逐季贡献值。这会误判完整的合理替代分析。

为每题区分：核心结论所需断言、可选支持数字、仅用于内部自查的计算。不要要求最终答案写出“残差=0”或所有中间变量；有可见工具证据可用于辅助核验，但最终解释仍要回答业务问题。

S05：整体毛利率、季度判断、完整贡献分解与勾稽是核心。若采取不同精确分解，其逐季贡献可不同，应按该方法重新核验，不强制命中现有 rate_contrib/mix_contrib 值。简单平均对照是可选说明，不因未提到就判失败。

S07 的 forbidden_claims 应限定“无依据断定持续性/根因”；可以正确地说“报表经营利润与经营利润率显著改善，但持续性未知”。不能把“盈利改善”这个表面结论一律禁掉。

### 3.4 S07 evaluator 背景混了表格列

`gold_evaluator_side.layer3_followups` 写调整后经营利润 `631,046/497,341`。直接检查 `FY26Q1_140820250742.pdf` p10：631,046 是本期调整后经营利润，497,341 是同一期调整后除税前利润，不是上年经营利润。

应写本期/上年调整后经营利润 **631.046/572.214 百万美元**。该明细继续留 evaluator 背景，不成为 S07 核心评分必答项。四列引用原文可保留，但结构化解释必须明确列与期间。

### 3.5 PDF 交叉引用没有验证“数字属于该页该期间”

自查脚本对 DB 来源的 pdf_crossref 只检查页面存在，未核对对应数字、期间和行列。已有明确错误：

- S01/S06 的 FY2025Q4、FY2026Q1 存货与上年应收/应付，统一指向 FY27Q1 p14/p15；这些页资产负债表比较的是 2026-06-30 与 2026-03-31，没有 2025-06-30/2025-03-31 余额。
- 正确上年来源可使用 `FY26Q1_140820250742.pdf`：存货 8,742,635、应收 10,796,573 在 p15，应付 14,187,753 在 p16；p15 比较栏也有 2025-03-31。
- S01/S06 的成本精确值 22,490,797 在 FY27Q1 p12，不是当前标注的 p5。摘要的舍入数字可以作量级核对，但不能冒充精确输入来源。

逐条修 pdf_crossref，不要简单给所有输入换成同一页。单季来自直接表或累计差分需区分；若只有摘要取整值，标 crosscheck 类型、单位与舍入容差。DB SQL 仍是可用取数证据，但“DB/PDF 双证一致”的声明应以实际逐行核对为准。

不必把本次定位问题升级为重做 ETL：先修 evaluator 的来源锚点、自查声明与脚本验证条件。源码缓存匹配、数字在页面出现也只能作为辅助；关键行列和期间仍要核对。
