## 1. 最后一轮交付不应自动等于任务未完成

位置：agent/subagents.py 的 delivering/finalized；agent/multi.py:535 的 `partial = bool(r.finalized or r.steps_exhausted)`。

M3 将最后一轮改成最大轮数之内的正常交付轮，但沿用了 M2“额外抢救轮一律 blocked”的规则。因而 Worker 即使在最后允许的一轮返回合法 JSON、声明任务完成且没有 missing_inputs，也会自动变 blocked，并被程序补出一条“未登记具体缺口”。这把交付时机误当成任务是否完成的证据。

离线复现：n1→n2；mock Worker 返回 finalized=True、execution_status=completed、missing_inputs=[]；经真实 _tool_execute 后，n1 为 blocked，程序补一条缺口，n2 不就绪。此复现证明分类规则有问题，不证明 mock 的业务任务确实完成。

修法：finalized 只记录“在最后一轮交付”，不直接决定完成状态。Worker 明确报告完成/部分完成及缺口；程序校验产物协议、引用和节点完成要求，语义是否完成仍可交 Reviewer 检查。证据或目标未完成才 blocked，协议失败才 failed。不要仅凭 missing_inputs 为空自动认定完成，也不要因最后一轮交付自动制造缺口。依赖前置校验与最终审查保持原有严格度。

补两种实际入口测试：最后一轮交付完整有效产物可 completed、下游就绪；最后一轮仅交部分产物仍 blocked、有明确缺口。两者都不能超出子轮数。现有 W1 测试只覆盖后一种，不能发现前一种误拦。
