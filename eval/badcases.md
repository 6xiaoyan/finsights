归因方法：失败 trial 的 trace（final_answer 的 claims 与正文）与 gold 口径（`eval/generators/template_l1_l2.py` → `fincalc.calc.working_capital`）逐一对照，必要时用 v0 自己引用的输入重算。

## v0（基线 text2sql，L1 1.00±0.00，L2 0.78±0.10）

| trial | 归类 | 根因分析 |
|---|---|---|
| l2_0001 t2（CCC，答 21.9 / gold 21.42） | 纯算术错误 | 口径与取数全对：用平均余额×实际天数 91，DSO/DIO/DPO 输入与 gold 管道一致；但"心算"各环节均偏差（宣布 49.38/51.06/78.54，按其自引输入重算应为 49.49/51.12/79.19 → CCC=21.42，与 gold 精确一致）。v0 无确定性计算工具，LLM 手算多位除法系统性出错。 |
| l2_0002 t1（D 厂商 DSO 同比变化，答 +0.35 / gold −2.9） | 计算口径错误 | 用期末应收账款代替平均余额（答案自述"期末应收账款 ÷ 季度日均收入"），题目与 gold 都要求平均余额口径；v0 无语义层锚定口径，同题 t2 通过、t1/t3 漂移，呈随机口径选择。 |
| l2_0002 t3（同上，答 +0.9 / gold −2.9） | 计算口径错误 | 同 t1：期末余额口径 + 由错误基期得错误差值。 |
| l2_0003 t2（HP DIO，答 72.9 / gold 68.62） | 纯算术错误 | 输入全对（平均存货 8,265.5、COGS 11,081、92 天），表达式也写对（92 ÷ (11,081/8,265.5)），但最后一步除法算错：正确值 68.624（重算即 gold）。与 l2_0001 同类——v0 的心算在最后一步翻车。 |

**v0 结论**：L2 失败 4 trial 分两类——**手算算术错误**×2、**口径随机漂移**×2。两者分别由 v1 的确定性工具（`query_metric` 语义层统一口径、`calc`/fincalc 代码计算）针对性解决；这正是 PRD 6.8 预期 v1 > v0 的机制。

## v1（P4 agent，L1/L2 正式评测）

### 首轮 run 20261001-212749：L1 0.92±0.08、L2 0.39±0.14 → 低于 v0，V4.45 FAIL（compare 判定"显著"）

| trial | 归类 | 根因分析 |
|---|---|---|
| l2_0001 t2/t3（CCC 21.70 / gold 21.42） | 工具静默降级 | 模型只传 `periods=["FY25Q1"]`，`working_capital` 的 `_expand_periods` 不前补一期 → fincalc 首行无 LAG，**期末值静默代替平均余额**（模型答案自己承认"因缺上期期末数，工具以期末值代替"）。口径承诺与实现不符，属工具缺陷。 |
| l2_0002 t1–t3（D 厂商 DSO 同比 −4.79 / gold −2.9） | 工具静默降级（同上） | 传非相邻期 `["FY24Q2","FY25Q2"]`，窗口起点 FY24Q2 无上一期 → 基期 DSO 用期末口径 41.07（与 v0 的口算漂移殊途同归的错值）。 |
| l2_0003 t1–t3（HP DIO 69.38 / gold 68.62） | 工具静默降级（同上） | 单期调用，期末 8,356 代替平均 8,265.5。 |
| l2_0005 t1/t2、l2_0006 t1（0.125067 / gold 12.51 等） | claim 单位错位 | 正文正确（"环比 +12.51%"），但 claim.value 抄了 variance 工具的小数原值 0.125067；打分器按题面单位（pct）比对。verifier/store 有 ×100 换算所以护栏不拦——是**表达约定缺失**，不是计算错误。 |
| l1_0003 t1（22244 / gold 222.44 亿） | claim 单位错位 | 问"亿美元"答了百万原值；同题 t2/t3 正确，属随机漂移。 |

**首轮结论**：v1 的取数与计算管线本身没有错（所有输入与 gold 管道一致），失败集中在两类系统性缺陷：
1. `working_capital` 单期/非相邻期时静默退化为期末口径（确定性偏差，3 题 8 trial 全栽）；
2. claim.value 单位约定未写入 system prompt（小数 vs 百分数、百万 vs 亿）。

**修复（commit 17a181c，均为 agent 侧，未动任何检查项）**：
- `agent/tools/data.py`：working_capital 自动向前补一个财年季度（`_prev_fiscal`），回归测试 `test_working_capital_single_period_keeps_avg_basis`（123 passed）；离线复核：Lenovo FY25Q1 CCC=21.4246、HP FY25Q3 DIO=68.6243、Dell DSO 同比 −2.91，与统一口径一致。
- `agent/prompts/system.md` 铁律 3：claim.value 用题面单位（12.51 不写 0.125；222.44 亿不写 22244 百万），核验自动换算。
- 工具描述同步"自动向前补一期"。
