# 归因数据集如何选题、审核和沉淀能力

整理日期：2026-10-05。本文记录当前已确定的方法与已完成的选题工作，不把待修订、待评测或待验证的目标写成成果。

## 1. 面试时可以怎样介绍

> 我们先从联想公开财报中整理约 50 条候选，再根据业务重要性、时间与口径清晰度、数据支持、推理区分度和方法迁移性选出首批 10 条。不是直接把管理层解释当标准答案，而是把它与结构化数字能够支持的结论分开。审核中发现有些参考答案依赖数据库缺少的调整项，有些把相关变化写成了确定原因，所以先修数据和评分边界，再准备运行基线、人工分析 bad case 和改进 harness。
>
> 我们希望沉淀的是通用的归因能力，例如联合看余额与流量、分解利润变化、检查权重与口径、比较竞争解释。预测是后续希望验证的能力，目前没有用归因成绩证明预测能力提升。

个人贡献据实际描述：参与定义业务目标、选题标准、审核裁定与优化方案；其他模型完成的抽取或代码实现不要说成自己全部独立完成。首批题目前仍需返工，尚未完成这批题的基线运行或性能提升验证。

## 2. 什么叫高质量题

**高质量题能够促使 Agent 从真实数字发现变化、验证解释、排除错误判断，并留下可以迁移的分析方法。** 最新、最长、最难或最容易让模型出错都不单独等于高质量。

| 标准 | 如何判断 | 为什么有用 |
|---|---|---|
| 业务重要 | 分析影响收入、盈利质量、现金占用或周转判断 | 把优化资源花在有实际意义的问题上 |
| 时间关系清楚 | 事件、期间、比较窗口、披露日期明确 | 防止累计/单季混用和时间倒置 |
| 数据支撑 | 必要真实数字可取得，结论与证据对应 | 防止将猜中管理层文字当推理能力 |
| 推理区分度 | 需要联合指标、分解或验证，并排除一个合理但错误的解释 | 找到模型真正需要改进的推理环节 |
| 方法迁移 | 换季度/公司仍可使用同一分析关系 | 沉淀通用能力而不是案例记忆 |

数据支撑与逻辑合理是进入正式调优的门槛。重要且暂缺明细的题放后备池，不能靠泄漏答案越过门槛。门槛通过后，再比较业务价值、推理区分度与迁移性，不要求先造一个貌似精确的综合分数。

时间重要包含两个层面：选择有意义的事件与经营阶段，以及明确先后关系和可比期间；并不等同于永远优先最新季度。

## 3. 用真实表象制造区分度

例如存货余额增长可能让模型直接认定周转同幅恶化。高质量题要求进一步看平均存货、单季成本与天数，计算周转变化；再判断哪些经营原因仍需要额外数据。

另一些典型冲突：

- 毛利率下降，经营利润却增长：拆收入规模、毛利金额与净费用。
- 费用率下降，费用金额却增长：区分规模摊薄与绝对降本。
- 半年亏损扩大，第二季度却减亏：拆期间与比较基准。
- 一个分部增长快，但金额贡献未必最大：看基数、金额与抵销。
- 报表利润下降，调整后增长：核对调整口径与现金/非现金性质。

难度来自真实冲突与多个必要步骤，不来自错误数字、含混口径、缺失必需数据或题面预设结论。

## 4. 区分财务分解与经营因果

`经营利润=毛利-净经营费用` 的桥可以量化变化发生在哪一层；它不自动证明需求、竞争、策略或效率变化造成了结果。

参考答案分三层：

1. **确定性事实与分解**：真实数字、期间、公式与贡献加总。
2. **经营假设与边界**：哪些解释与数字相容，哪些已排除，哪些尚无法区分。
3. **后续验证需求**：补查什么真实数据，观察哪些指标能够区分假设。

管理层讨论帮助人发现值得分析的事件，也提供外部解释参照，但它是带来源的判断，不自动是真实因果。不能要求只看集团数字的 Agent 精确复述管理层原因。

例如库存、应收与应付变化可以反映选定余额的净占用；现金余额增长不能证明备货没有占用现金，也不能单凭这些余额确定全部融资来源。

## 5. 开放业务题与定向诊断题

业务题用于测试 Agent 自主发现并选择分析路线，例如“这一季度盈利改善质量如何？”；诊断题可明确要求利润桥或 DIO，用来定位取数/公式错误。

同一事件可以有两种问法，但不是两个独立样本，不应一边拿诊断题提示解法、一边把开放题放到留出集证明泛化。运行侧仍需清晰的范围、单位与指标定义；开放不等于故意不告诉模型必要业务口径。

经营解释、gold 与评分清单保留在 evaluator 侧。真实数字及普通会计科目定义可以进入业务数据层，不能把答案或专门解题流程包装成元数据。

## 6. 审核和调优怎样衔接

顺序是来源与数字 → 逻辑 → 可测性 → 代表性 → 修订 → 冻结版本 → 跑基线 → 人工诊断 → 选择通用改动 → 验证。

入选不等于 PASS。运行失败也不一定是归因能力差，先区分：

- 源数据/符号/单位错误。
- 参考答案错误或评分要求越界。
- Agent 取数范围或科目错误。
- 计算与指标定义错误。
- 证据充分但分析逻辑错误。
- 结论超出证据、未验证假设被当事实。
- 预算、工具或运行可靠性问题。

只有诊断后才能决定改数据层、取数规则、评分标准还是推理 harness。每次优先改变一项，每题每版本运行一次；记录版本、输入、轨迹和修改影响。

抽取更多题不能替代审核，修完全部候选也不是开始优化的必要条件。先选一小批覆盖不同方法的可测题，保留少量基础题防止改动破坏取数和计算能力。

## 7. 如何沉淀通用方法、为预测准备

从多个案例中归纳少量方法：核对期间/单位 → 联合看金额与比率 → 分解贡献并勾稽 → 比较竞争解释 → 标明证据缺口 → 提出可验证的后续观察。

不是每条案例生成一个 skill，也不是把财报参考答案塞进案例检索库。改动应让模型在新案例中更会选择数据、检查假设与限制结论，而非记住“联想某季度因为什么变化”。

后续观察可写成条件关系，例如“若库存积压假设成立，在可比需求与成本条件下，应进一步检查周转、成品占比、库龄和减值”。它用于指导验证，不要求这些指标一定同向变化，更不等于已经做出准确预测。

归因可能帮助建立候选驱动变量、业务关系和失效条件。这些是预测的准备工作；未来还需要独立的时点隔离和预测评测才能验证是否有效。当前不构造回测集，不把看到未来结果后的解释计为预测能力。

## 8. 如何避免“调优后分数涨了”的假象

开发与留出按真实事件及重叠数据窗口分组，不只按不同 case_id。相同季度的库存/DIO/CCC、同一利润调整项在多份公告的重复披露、半年与九个月的重叠分析都要检查。

留出题的运行结果或错误一旦参与修改，就成为开发数据，需要另选验收案例。比较版本时同时固定可见数据、query 与评分定义，报告覆盖范围；不能把补数据、换题或降低评分要求带来的变化全说成推理能力提升。
